# The hostile-HTML corpus: the P0 body-view spike's input, and NFR-40 method 2's.
#
# Every sample is loaded **raw** — not sanitized — into a body view configured exactly as the
# application configures it. That is the stronger test: N-1 and NFR-20 are properties of the
# view, and a view that held only because the sanitizer had already removed the attack would be
# proving the sanitizer. The roadmap's pass condition is absolute: no sample achieves script
# execution, network egress, or storage shared with another view, on either engine.
#
# Format: a line `=== <id>` starts a sample; everything up to the next such line is its HTML.
# Lines starting with `#` before the first sample are comments. The probe expands:
#
#   {{EXEC}}      a script statement that loads sift-resource://probe/exec and posts to the
#                 execution bridge. Reaching either is script execution.
#   {{FILE_CSS}}  a file: URL to a stylesheet the probe writes, which styles `div.f` with a
#                 background from sift-resource://probe/chain.
#   {{ID}}        the sample's id.
#
# and prepends a sentinel image at sift-resource://probe/ok, which proves the document loaded
# at all: a sample that observed nothing because nothing rendered proves nothing.
#
# The probe's markers are what it judges by:
#
#   sift-resource://probe/exec   reachable only by script
#   sift-resource://probe/chain  reachable only if a data:, file: or blob: resource loaded —
#                                the schemes WebKit resolves without consulting any handler
#   sift-resource://probe/nav    reachable only if a navigation proceeded
#   http(s)://egress.invalid/    any load under a foreign scheme is egress
#   192.0.2.1:9                  TEST-NET-1: where the socket-level vectors (preconnect,
#                                dns-prefetch, websockets) aim. **No detector observes these on
#                                WKWebView** — they reach no handler, and the engine's sockets
#                                are not visible from the probe's process — so their samples
#                                are carried for the engines and detectors that can, and for
#                                the script a websocket needs, which the execution detector does
#                                see.
#
# Each sample is also run in a control view — script on, no rule list, no CSP, no navigation
# policy — so every detector is shown to fire on this engine before its silence in the
# hardened view is counted as a pass.
