# Decision index

Every architectural decision, what was rejected, and **the one document that owns it**. D-1 through D-38
settled the original design; D-39 through D-44 close surfaces that were unowned rather than decided; D-45
through D-58 close what an implementer would otherwise have had to invent alone; and **D-59 onward are
what a build actually runs into** — the byte layouts, the boundary's representation, the process
lifecycle, the screens, and the project's own build and verification machinery. That last group is the
largest and the least glamorous, and it exists because the set was complete on *what* and *why* while an
engineer starting work had to invent the answers to *in what order*, *in what shape*, and *how many
files*.

Rationale lives in the owning document, next to the design it explains. This page is an index. The "why
it is contestable" column is deliberate: a decision recorded without its weakness is an assertion, not a
decision, and the weakest column entries are where a reviewer should push.

**Identifiers are stable and MUST NOT be renumbered.** To change a decision, amend the owning document
**and** this row. Leaving the two disagreeing is a defect.

Two decisions here — D-1 and D-2 — **reverse earlier positions**. Their owning documents state the
reversal explicitly rather than hiding it, because the reasoning that produced the original answer is what
tells a future reader when to revisit. D-2 is the sharpest case: it was reversed because its stated
rationale was found to be factually wrong about the rendering engine, not because the trade-off moved.

| **D-14** | Network conditions | A small purpose-built abstraction with per-platform backends | An existing cross-platform crate | Building anything is a cost; this one is justified only because nothing unified exists and the scope is tiny | [runtime/network-conditions](runtime/network-conditions.md) |

| **D-16** | Memory metric | Footprint on macOS, PSS on Linux | Resident set size | Two metrics instead of one, and neither is what most tooling reports by default | [runtime/observability](runtime/observability.md) |
| **D-17** | Shell boundary | A narrow C ABI from the presentation layer | A serialized protocol retained in-process | Every crossing type needs an explicit representation and hand-written ownership rules; memory-safety bugs are possible here | [architecture/shell-boundary](architecture/shell-boundary.md) |
| **D-18** | View-model delivery | Observed windows with ordered change notifications and cancellation | Shell polling; pushing whole result sets | Diff computation in the layer is unearned if both shells end up reloading anyway | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-19** | Async runtime | One multi-threaded work-stealing runtime plus a blocking pool | A current-thread runtime per subsystem; a thread per connection | A pinned runtime would make thread-local attribution sound by construction; fairness has not been measured to matter | [architecture/overview](architecture/overview.md) |
| **D-20** | Allocator | mimalloc, with purge issued by the pressure governor | jemalloc with background purge; the system allocator | Rests on the unmeasured claim that a background purge thread is a meaningful share of the NFR-11 budget | [runtime/memory-pressure](runtime/memory-pressure.md) |
| **D-21** | Embedded database | SQLite, named explicitly | A key-value store with a separate index | Names a C dependency, and makes D-5's conceded ranking weakness concrete rather than resolving it | [storage/data-model](storage/data-model.md) |
| **D-22** | Encryption at rest | Per-account database keys; convergent per-blob keys wrapped per account | One device key for blobs; per-account blob stores with no dedup | Per-blob key wrapping is the complexity most likely to break the store; dropping dedup is the retreat | [storage/encryption](storage/encryption.md) |
| **D-23** | Content address | BLAKE3, chosen to avoid a hardware mandate rather than for speed | SHA-256, with or without required acceleration | SHA-256 is what a security reviewer expects; choosing otherwise costs an explanation forever | [storage/cache-and-blobs](storage/cache-and-blobs.md) |
| **D-24** | Allocation attribution | The subsystem tag travels in the allocation; task-scoped, re-established per poll | Tagging on allocation only; per-subsystem heaps; development-only | Per-subsystem heaps would be free of overhead if the pipeline copies at stage boundaries anyway | [runtime/observability](runtime/observability.md) |
| **D-25** | Timing wheel | A Sift-owned wheel armed through platform coalescing timers | The runtime's timer; the platform job scheduler | A component built rather than used; unearned if the runtime's timer turns out to meet NFR-11 | [runtime/scheduling](runtime/scheduling.md) |
| **D-26** | HTML parsing | A spec-conformant tree builder with Sift's own policy over it | A streaming rewriter; an existing sanitizer crate | Materializes a tree for every message inside a 30 ms budget shared with the cascade | [rendering/sanitizer-invariants](rendering/sanitizer-invariants.md) |

| **D-28** | Internal scheme | Per-view unguessable capability tokens | Content-hash addressing; message and part identifiers | Puts opaque tokens in the debug view, degrading the product's most useful diagnostic surface | [rendering/webview-isolation](rendering/webview-isolation.md) |
| **D-29** | Image handling | Original bytes after bounded validation; decode only for classification | Universal transcoding; untouched pass-through | Universal transcoding would give one decoder path and strip metadata by construction | [rendering/content-blocking](rendering/content-blocking.md) |
| **D-30** | TLS | Rust TLS verifying against the OS trust store | The platform TLS stack; a bundled root store | The platform stack would match what the user's other clients do on the same machine | [mail/provider-model](mail/provider-model.md) |
| **D-31** | IMAP client | Hand-written, covering the read-and-triage subset | An existing crate, as published or forked | "Small subset of IMAP" has defeated better-resourced projects; this shows up as schedule in P2 | [mail/providers/imap](mail/providers/imap.md) |
| **D-32** | Schema migration | Versioned, forward-only, never requiring resync | Additive-only schema; rebuilding derived state | Forward-only makes downgrade unsupported once a migration has run | [storage/data-model](storage/data-model.md) |
| **D-33** | Distribution | Platform channels only — Cask on macOS, Flatpak on Linux; the Mac App Store is deferred, not rejected, and is reconsidered only with D-113's licensing question | A signed delta self-updater; the App Store from the first release | Forfeits any ability to push an urgent fix, in a product whose adversary sends the input; until the store is reconsidered, macOS reaches only the technically-inclined half of its audience; and makes every address a shipped build calls permanent, so an endpoint Sift operates is a commitment for the life of the oldest build still installed. A reinstated list endpoint reopens D-111 and MUST version its address and payload before the first build that calls it ships; D-114 answers the crash-report endpoint the same way, by not having one | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-34** | Trace format | An established viewer's protobuf trace format | JSON trace events; a sampling-profiler format | More machinery than appending JSON, and moot if the soak harness consumes counters separately | [runtime/observability](runtime/observability.md) |
| **D-35** | Crash reporting | Backtraces and counters only; no heap; OS collectors disabled | Scrubbed minidumps; no crash reporting | Accepts worse post-mortem debugging on exactly the hostile-input failures that matter most | [security/privacy](security/privacy.md) |
| **D-114** | Crash-report delivery | A report is a local file, only the most recent kept, and deleted when the user dismisses its launch notice; the user reads it in full and saves a copy through the platform's save dialog to send by their own means; Sift makes no connection for it and no build holds an address for one | Operating a crash-report endpoint; dropping crash reporting from the first release | Reports arrive only when a user bothers, skewed towards technical users, and cannot be counted or correlated, so a widely crashing build is learned about late; a crash loop keeps only its last report | [security/privacy](security/privacy.md) |
| **D-36** | OAuth redirect | A registered URI scheme handler, with the callback returned to the running process by the platform's own authentication session where it offers one; a shell reports the schemes its bundle claims and the core decides whether the configured client's is among them | A loopback listener; the device authorization flow; asking a shell whether the scheme is registered | Providers test the loopback path most thoroughly, a failed scheme registration is hard to diagnose, and the authentication session is a platform affordance rather than a portable one | [security/credentials](security/credentials.md) |
| **D-37** | Sender infrastructure | A bundled list, first-party only when the origin is attested | Accepting the breakage; widening without attestation | A flat list widens any attested sender to any listed host; the attested-pair map is the correct refinement | [rendering/sender-origin](rendering/sender-origin.md) |
| **D-38** | Reconciliation | Silent for concurrent change; animated with a notice when Sift's own action failed | Silent everywhere; animating everything; blocking | Assumes users perceive the two cases differently; if they do not, the second path buys nothing | [mail/mutations](mail/mutations.md) |
| **D-39** | Encrypted and signed mail | Deferred, with a named seam — a decryption stage between pipeline stages 1 and 2 and a key store beside credentials | Implementing S/MIME or OpenPGP now; rendering the armored block as text | Deferring is cheap to write and expensive to honour: the seam touches blobs, the index and D-35, none of which was designed with it in mind | [product/scope](product/scope.md) |
| **D-40** | Junk reporting | Its own intent pair against a declared capability | Treating report-spam as a move to the junk folder; omitting it | Widens FR-13's mutation set, which this set otherwise treats as closed; it is the one place scope moved rather than being clarified | [mail/mutations](mail/mutations.md) |
| **D-41** | Contact names | Read-only from the platform contact store, on demand, nothing stored | Syncing a provider contacts API; deriving an address book from observed mail | Users whose contacts live only in their provider get nothing, which on Microsoft 365 is the common case | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-42** | Database encryption | A page-level encrypting layer beneath the database engine — keyed per account for account databases, per installation for the two installation-scoped stores | Application-level column encryption; relying on whole-disk encryption | A crypto layer beneath a C dependency where a bug is total loss of an account, not a parse failure | [storage/encryption](storage/encryption.md) |
| **D-43** | Content addressing | Address and blob key derived with keyed BLAKE3 under a per-installation secret; the shared blob index and the installation policy store encrypted under it | Bare plaintext hashes; per-account indexes | One secret whose compromise re-enables known-file confirmation across every account at once, and now also unseals the installation-wide half of the allowlist | [storage/encryption](storage/encryption.md) |
| **D-76** | Page format | Per-page authenticated seal, nonce from page number plus a durable write counter, and a header carrying magic, format version, key identifier and counter high-water mark | Nonce from the page number alone; a random nonce; one seal over the whole file | The counter is durable state that must be monotonic across crashes, which is exactly the kind of thing that is subtly wrong for a long time | [storage/encryption](storage/encryption.md) |
| **D-106** | Per-file key derivation | Each file is sealed under a key derived by role from the key its owner holds; the key identifier is derived from the same owner by a separate context | Sealing an account's two files under the account key itself | It corrects a nonce reuse that no existing test could fail, and the derivation contexts are permanent — changing one is a key destruction wearing the clothes of a refactor | [storage/encryption](storage/encryption.md) |
| **D-107** | Sealing mechanism | The page layer is a SQLite VFS that translates every logical byte range onto sealed blocks, with the file's own length sealed as its own page and the write counter reserved ahead of use; `locking_mode=EXCLUSIVE`, `mmap_size=0`, `temp_store=MEMORY` and `page_size=4096` are asserted against a live connection | Adopting SQLCipher; an application-level encrypted column; trusting the pragmas to have been set | It is unsafe FFI on the path where a mistake loses an account, and three of its four required pragmas fail silently — a memory-mapped read simply bypasses the layer, and a shared-mode write-ahead index sits in the clear beside a sealed database with nothing to see | [storage/encryption](storage/encryption.md) |
| **D-108** | Installation container | A sealed registry beside the account files, holding identity, ordinal, kind, display name and the write authorisation; identity is 128 random bits, ordinals are monotonic and never reclaimed, and each account's queue is rebuilt from its journal at open | A file of account names; a sequential identity; keeping the write flag in the account's own store | The registry becomes a single point whose loss orphans every account's files at once — recoverable, because the files are unreadable without keys the registry does not hold, but recoverable as *deletion* rather than as repair | [storage/data-model](storage/data-model.md) |
| **D-110** | Write authorisation | A newly added account is read-only: intents are built, checked, journaled and applied optimistically, and the step that issues them to the provider does not happen until writes are authorised for that account, durably and explicitly | An account that writes as soon as it is added; a global read-only mode; a confirmation on each first mutation; keeping the flag in the account's own store | A user who does not find the control has a client that appears to accept triage and never performs it — the failure this creates in exchange for the silent, unrecoverable one it prevents | [mail/mutations](mail/mutations.md) |
| **D-109** | Redirect scheme | The callback scheme is derived from the registered OAuth client where the provider requires it, and from the bundle identifier otherwise; the bundle registers both, and the client is per-installation configuration rather than a baked constant | A single fixed scheme; a loopback redirect; baking one client identifier into the repository | A build with no client configured registers an empty second scheme and cannot sign in to anything, which is correct and is also a first-run failure that looks like a bug until somebody reads the message | [product/platform-baseline](product/platform-baseline.md) |
| **D-111** | List delivery | Every filter list and the sender-infrastructure list ship inside the binary, fixed at build time, and change only through the platform channels; nothing fetches a list at run time, and a subscription selects among bundled lists | A Sift-operated endpoint serving signed lists; fetching public lists from their upstreams; subscribing to a list by address | Lists are only as current as the user's upgrades, which leaves the blocker weaker against new trackers than any browser's, and it makes R-11 permanent for lists as D-33 does for code | [rendering/content-blocking](rendering/content-blocking.md) |
| **D-112** | Bundled artefacts Sift does not own | EasyList and EasyPrivacy, taken under GPL-3.0, ship in the Cask and Flatpak builds and not in the App Store build; the email list and the sender-infrastructure list are written by the Sift project; every font is under the SIL Open Font License 1.1 — Liberation Sans, Serif and Mono, Carlito, Caladea and Gelasio for metric compatibility, then Noto Sans, Noto Sans CJK and Noto Color Emoji — and ships unmodified | The public lists in every channel under their share-alike option; dropping the App Store channel; permissively licensed public lists everywhere; lists that forbid commercial use | The App Store build, which reaches the less technical audience, blocks less by default than the other two, and the user cannot see that from the store listing | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-113** | Licensing and contributions | AGPL-3.0 only, inbound as outbound; no contributor agreement while D-33 defers the App Store. The agreement question reopens if and when that channel is reconsidered, and is answered before the first external contribution the channel would need | Requiring a contributor licence agreement now; relicensing permissively; keeping the App Store in the first release | Each external contribution merged under AGPL-3.0 alone needs its author's consent, or replacing, before a store build can carry it, so reconsidering the store grows costlier with every one | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-96** | Portal detection | Detected from the behaviour of connections to the user's own providers; no detection endpoint of any kind | Probing a well-known connectivity-check URL; a Sift-operated probe endpoint | Detection is weaker on networks that pass TLS through and interfere only with plain HTTP, which Sift never speaks | [runtime/network-conditions](runtime/network-conditions.md) |
| **D-100** | Bidi and normalization | Bidirectional controls are isolated rather than stripped; normalization precedes truncation; the normalized form is the indexed form | Stripping controls; truncating first; normalizing for display only | Isolating leaves attacker-chosen control characters in the string, and the safest-looking answer is to strip | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-105** | Gate kinds | A conformance gate requires a target be met; a derivation gate requires it be produced and recorded. P0 gates NFR-8, NFR-9 and the reading peak as derivation | Reading P0's gate as conformance; removing them from P0; letting a phase self-certify | A derivation gate is weak by construction — it can be satisfied by an honest and terrible measurement, and nothing states what NFR-8 must not exceed | [product/roadmap](product/roadmap.md) |
| **D-104** | Versioned artefacts | The two installation-scoped stores carry schema versions and the refuse-a-newer-store rule; D-44's digest carries its rule version, and a cross-version comparison is no corroboration | Versioning account stores only; an unversioned digest reindexed in place | The digest version will change approximately never, so it is a permanent per-row cost against a one-off event | [storage/data-model](storage/data-model.md) |
| **D-103** | Thread identity | A local identity assigned at creation; a linking message merges two threads with the older identity surviving; threads never split | Keying on the provider's conversation identifier or a normalized subject; splitting when the linking message is deleted | Never splitting means a wrong merge is permanent, and subject-normalization fallback can merge unrelated mail on a generic subject | [mail/threading](mail/threading.md) |
| **D-102** | Eviction and fetch | Eviction spares messages with queued intents or open readers, runs in batches to a low-water mark, and retires empty threads; a fetch is staged outside the store until complete, coalesces, and checks its declared length | Evicting purely by age and budget; evicting per insertion; provisional addresses for partial content | Sparing queued messages lets a hard-capped budget be exceeded by the queue's working set, bounded only by L-17's seven days | [storage/cache-and-blobs](storage/cache-and-blobs.md) |
| **D-101** | Settings surface | Enumerated with defaults, organized by the installation-versus-account scope storage already uses | Organizing by topic; leaving defaults to each shell; a surface that accretes per feature | Scope is a storage-shaped organization shown to users, who do not know what an installation is | [architecture/ui-surface](architecture/ui-surface.md) |
| **D-99** | Selection | A set keyed on identity with an anchor, surviving sort and cleared by scope change; query selections cross as a query and a count, expanded once at the gesture; a mixed selection resolves to the capability intersection | Enumerating a large result selection; the union of capabilities; refusing cross-account selection | The intersection silently shrinks available actions as a selection widens, with nothing saying why | [architecture/presentation-layer](architecture/presentation-layer.md) |
