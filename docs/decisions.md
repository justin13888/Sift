# Decision index

Every architectural decision, what was rejected, and **the one document that owns it**. D-1 through D-38
settled the original design; D-39 through D-43 close surfaces that were unowned rather than decided.

Rationale lives in the owning document, next to the design it explains. This page is an index. The "why
it is contestable" column is deliberate: a decision recorded without its weakness is an assertion, not a
decision, and the weakest column entries are where a reviewer should push.

**Identifiers are stable and MUST NOT be renumbered.** To change a decision, amend the owning document
**and** this row. Leaving the two disagreeing is a defect.

Two decisions here — D-1 and D-2 — **reverse earlier positions**. Their owning documents state the
reversal explicitly rather than hiding it, because the reasoning that produced the original answer is what
tells a future reader when to revisit. D-2 is the sharpest case: it was reversed because its stated
rationale was found to be factually wrong about the rendering engine, not because the trade-off moved.

| ID | Decision | Chosen | Rejected | Why it is contestable | Owner |
|---|---|---|---|---|---|
| **D-1** | UI runtime | Native shell per platform; a web engine only for message bodies | A web UI hosting the whole interface | ~2× the UI work; reverses an earlier decision. Revisit only if the memory delta measures under ~50 MB *and* a zero-wakeup web UI is demonstrable | [architecture/ui-shell](architecture/ui-shell.md) |
| **D-2** | Process model | One resident process; the engine's content process is disposable | A resident daemon plus a separately launched UI process | Toolkit residue is unmeasured, and GTK4's renderer may make the Linux floor materially worse than the macOS one | [architecture/process-model](architecture/process-model.md) |
| **D-3** | Body rendering | A separate hardened document with script off | Rendering into the app's own DOM with scoped CSS | Costs an extra process. But scoped CSS is defeatable, so the alternative is not really a boundary | [rendering/webview-isolation](rendering/webview-isolation.md) |
| **D-4** | Unified inbox in v1 | Yes | Per-account views only | Cross-account paging and sort over N databases is genuinely hard; cutting it simplifies a lot | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-5** | Local search | The embedded database's full-text index | A dedicated embedded search engine | Weaker ranking and clumsier phrases and wildcards. Ranking *is* the product; revisit on measured failure | [storage/search](storage/search.md) |
| **D-6** | Storage layout | One database per account | A single shared database | Blocks cheap cross-account queries and forces an in-memory merge — which D-4 then depends on | [storage/data-model](storage/data-model.md) |
| **D-7** | Gmail push | IDLE as a doorbell plus API delta | Pure API polling | Two auth paths and two connection lifecycles for latency users may not perceive — and it is disabled on cellular anyway | [mail/providers/gmail](mail/providers/gmail.md) |
| **D-8** | Core language | Rust throughout the core | Go, C++ | The Rust GUI ecosystem is immature — mitigated by not using it; the shells are native | [architecture/overview](architecture/overview.md) |
| **D-9** | Platform scope | macOS first, then Linux; no Windows | Three platforms simultaneously | Forgoes the largest desktop market, and makes the Linux shell a second full UI rather than a recompile | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-10** | Content blocker | A browser-grade filter engine as authority, compiled engine rules as backstop | A bespoke matcher, or engine rules alone | Two enforcement layers can disagree; that disagreement must be detected rather than silently resolved | [rendering/content-blocking](rendering/content-blocking.md) |
| **D-11** | First-party origin for email | Synthesized from authenticated sender identity, falling to null | The From header alone; everything same-origin; everything third-party | Legitimate service-provider-hosted images become third-party, breaking real mail — narrowed by D-37, which widens only for attested senders, not removed | [rendering/sender-origin](rendering/sender-origin.md) |
| **D-12** | Provider model | Location and Tags as separate axes, capability-driven | A flat folder model with labels as a Gmail special case | Adds a concept most providers name differently; the mapping must be right for all four or it is worse than a special case | [mail/provider-model](mail/provider-model.md) |
| **D-13** | Provider clients | Hand-written subset for Graph, generated client for Gmail; no other-language shim | A Go or similar SDK sidecar | Hand-written types drift from the schema unless CI enforces the diff | [mail/provider-model](mail/provider-model.md) |
| **D-14** | Network conditions | A small purpose-built abstraction with per-platform backends | An existing cross-platform crate | Building anything is a cost; this one is justified only because nothing unified exists and the scope is tiny | [runtime/network-conditions](runtime/network-conditions.md) |
| **D-15** | Linux distribution | Flatpak, to pin the engine runtime | Distro packages against the system engine | Narrows the install base and adds a packaging pipeline. But version skew is the dominant Linux rendering risk | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-16** | Memory metric | Footprint on macOS, PSS on Linux | Resident set size | Two metrics instead of one, and neither is what most tooling reports by default | [runtime/observability](runtime/observability.md) |
| **D-17** | Shell boundary | A narrow C ABI from the presentation layer | A serialized protocol retained in-process | Every crossing type needs an explicit representation and hand-written ownership rules; memory-safety bugs are possible here | [architecture/shell-boundary](architecture/shell-boundary.md) |
| **D-18** | View-model delivery | Observed windows with ordered change notifications and cancellation | Shell polling; pushing whole result sets | Diff computation in the layer is unearned if both shells end up reloading anyway | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-19** | Async runtime | One multi-threaded work-stealing runtime plus a blocking pool | A current-thread runtime per subsystem; a thread per connection | A pinned runtime would make thread-local attribution sound by construction; fairness has not been measured to matter | [architecture/overview](architecture/overview.md) |
| **D-20** | Allocator | mimalloc, with purge issued by the pressure governor | jemalloc with background purge; the system allocator | Rests on the unmeasured claim that a background purge thread is a meaningful share of the NFR-11 budget | [runtime/memory-pressure](runtime/memory-pressure.md) |
| **D-21** | Embedded database | SQLite, named explicitly | A key-value store with a separate index | Names a C dependency, and makes D-5's conceded ranking weakness concrete rather than resolving it | [storage/data-model](storage/data-model.md) |
| **D-22** | Encryption at rest | Per-account database keys; convergent per-blob keys wrapped per account | One device key for blobs; per-account blob stores with no dedup | Per-blob key wrapping is the complexity most likely to break the store; dropping dedup is the retreat | [storage/encryption](storage/encryption.md) |
| **D-23** | Content address | BLAKE3, chosen to avoid a hardware mandate rather than for speed | SHA-256, with or without required acceleration | SHA-256 is what a security reviewer expects; choosing otherwise costs an explanation forever | [storage/cache-and-blobs](storage/cache-and-blobs.md) |
| **D-24** | Allocation attribution | The subsystem tag travels in the allocation; task-scoped, re-established per poll | Tagging on allocation only; per-subsystem heaps; development-only | Per-subsystem heaps would be free of overhead if the pipeline copies at stage boundaries anyway | [runtime/observability](runtime/observability.md) |
| **D-25** | Timing wheel | A Sift-owned wheel armed through platform coalescing timers | The runtime's timer; the platform job scheduler | A component built rather than used; unearned if the runtime's timer turns out to meet NFR-11 | [runtime/scheduling](runtime/scheduling.md) |
| **D-26** | HTML parsing | A spec-conformant tree builder with Sift's own policy over it | A streaming rewriter; an existing sanitizer crate | Materializes a tree for every message inside a 30 ms budget shared with the cascade | [rendering/sanitizer-invariants](rendering/sanitizer-invariants.md) |
| **D-27** | CSS handling | Resolve the full cascade | Declarations only; a colour-bearing subset | The largest commitment in the pipeline and the first casualty if NFR-41 is missed; the retreat is visibly worse, not merely slower | [rendering/dark-mode](rendering/dark-mode.md) |
| **D-28** | Internal scheme | Per-view unguessable capability tokens | Content-hash addressing; message and part identifiers | Puts opaque tokens in the debug view, degrading the product's most useful diagnostic surface | [rendering/webview-isolation](rendering/webview-isolation.md) |
| **D-29** | Image handling | Original bytes after bounded validation; decode only for classification | Universal transcoding; untouched pass-through | Universal transcoding would give one decoder path and strip metadata by construction | [rendering/content-blocking](rendering/content-blocking.md) |
| **D-30** | TLS | Rust TLS verifying against the OS trust store | The platform TLS stack; a bundled root store | The platform stack would match what the user's other clients do on the same machine | [mail/provider-model](mail/provider-model.md) |
| **D-31** | IMAP client | Hand-written, covering the read-and-triage subset | An existing crate, as published or forked | "Small subset of IMAP" has defeated better-resourced projects; this shows up as schedule in P2 | [mail/providers/imap](mail/providers/imap.md) |
| **D-32** | Schema migration | Versioned, forward-only, never requiring resync | Additive-only schema; rebuilding derived state | Forward-only makes downgrade unsupported once a migration has run | [storage/data-model](storage/data-model.md) |
| **D-33** | Distribution | Platform channels only — App Store and Cask on macOS, Flatpak on Linux | A signed delta self-updater; one channel per platform | Forfeits any ability to push an urgent fix, in a product whose adversary sends the input | [product/platforms-and-distribution](product/platforms-and-distribution.md) |
| **D-34** | Trace format | An established viewer's protobuf trace format | JSON trace events; a sampling-profiler format | More machinery than appending JSON, and moot if the soak harness consumes counters separately | [runtime/observability](runtime/observability.md) |
| **D-35** | Crash reporting | Backtraces and counters only; no heap; OS collectors disabled | Scrubbed minidumps; no crash reporting | Accepts worse post-mortem debugging on exactly the hostile-input failures that matter most | [security/privacy](security/privacy.md) |
| **D-36** | OAuth redirect | A registered URI scheme handler | A loopback listener; the device authorization flow | Providers test the loopback path most thoroughly, and a failed scheme registration is hard to diagnose | [security/credentials](security/credentials.md) |
| **D-37** | Sender infrastructure | A bundled list, first-party only when the origin is attested | Accepting the breakage; widening without attestation | A flat list widens any attested sender to any listed host; the attested-pair map is the correct refinement | [rendering/sender-origin](rendering/sender-origin.md) |
| **D-38** | Reconciliation | Silent for concurrent change; animated with a notice when Sift's own action failed | Silent everywhere; animating everything; blocking | Assumes users perceive the two cases differently; if they do not, the second path buys nothing | [mail/mutations](mail/mutations.md) |
| **D-39** | Encrypted and signed mail | Deferred, with a named seam — a decryption stage between pipeline stages 1 and 2 and a key store beside credentials | Implementing S/MIME or OpenPGP now; rendering the armored block as text | Deferring is cheap to write and expensive to honour: the seam touches blobs, the index and D-35, none of which was designed with it in mind | [product/scope](product/scope.md) |
| **D-40** | Junk reporting | Its own intent pair against a declared capability | Treating report-spam as a move to the junk folder; omitting it | Widens FR-13's mutation set, which this set otherwise treats as closed; it is the one place scope moved rather than being clarified | [mail/mutations](mail/mutations.md) |
| **D-41** | Contact names | Read-only from the platform contact store, on demand, nothing stored | Syncing a provider contacts API; deriving an address book from observed mail | Users whose contacts live only in their provider get nothing, which on Microsoft 365 is the common case | [architecture/presentation-layer](architecture/presentation-layer.md) |
| **D-42** | Database encryption | A page-level encrypting layer beneath the database engine — keyed per account for account databases, per installation for the two installation-scoped stores | Application-level column encryption; relying on whole-disk encryption | A crypto layer beneath a C dependency where a bug is total loss of an account, not a parse failure | [storage/encryption](storage/encryption.md) |
| **D-43** | Content addressing | Address and blob key derived with keyed BLAKE3 under a per-installation secret; the shared blob index and the installation policy store encrypted under it | Bare plaintext hashes; per-account indexes | One secret whose compromise re-enables known-file confirmation across every account at once, and now also unseals the installation-wide half of the allowlist | [storage/encryption](storage/encryption.md) |
